# Retro: day-04 boards CRUD, full route layer (2026-11-09)

This milestone adds boards (FR-B1 to FR-B4) and `GET /tasks` (FR-T1), and scopes every board and task route to the caller (AC-2.7). The brief puts `authenticate` on Day 5, so for now the caller comes from a temporary stub.

## Non-obvious constraints found during PLAN, APPLY and VALIDATE

1. **Boards need an owner before auth exists.** `POST /boards` sets `ownerId` from the caller, but the brief adds `authenticate` with `week-01`. Decision: a temporary `actingUser` middleware (`api/src/middleware/actingUser.ts`) resolves every request to the seed user `dev@flowboard.test`.
   - Handlers read the caller through `requireUserId(req)`, so `week-01` doesn't change them.
   - The stub refuses to run in production (`500 ACTING_USER_DISABLED`).
   - It returns `500 ACTING_USER_MISSING` when the seed hasn't been run.
2. **403 is testable without auth.** A board created directly through Prisma for a second user belongs to someone other than the acting user, so the ownership tests (AC-2.7) land now instead of in `week-01`. Only the 401 cases (AC-2.6) wait.
3. **`req.user` is typed as optional.** A non-optional field would let a router mounted without its guard read `undefined.id` with no compiler error. `requireUserId` turns that mistake into a `401` instead. Its 401 branch can't be reached over HTTP, so `requestUser.test.ts` calls it directly.
4. **The seed email lives in three places:** `prisma/seed.ts`, the stub and `tests/helpers/factories.ts`. `src/` can't import from `prisma/` (`rootDir: src`). The duplicates in the stub and the factories go away with `week-01`.
5. **`createdAt` can be set on insert.** The "newest first" tests set explicit dates, so the order doesn't depend on two rows being inserted in the same millisecond.
