# Retro: week-01 complete: API, auth foundation, Prisma schema (2026-11-09)

This milestone adds register and login (FR-A1, FR-A2) and puts the `authenticate` guard on every board and task route (AC-2.6). The `actingUser` stub is gone. Every task create, update and delete now writes an AuditLog row in the same transaction as the task write (AC-6.3, synchronous until day-08).

## Non-obvious constraints found during PLAN, APPLY and VALIDATE

1. **The refresh token arrives before Redis does.** FR-A2 returns a refresh token now, but ADR-004 stores its `jti` in Redis, and Redis comes with day-06. Decision: sign the token now and add the `SET refresh:{sub}:{jti}` key with day-07.
   - No route accepts a refresh token yet, so nothing can use the unstored token.
   - A token issued before day-07 will fail its first refresh, because `DEL` returns 0. That's acceptable on a dev database.
2. **The audit write is synchronous for now.** It runs inside `prisma.$transaction` with the task write, so a change never commits without its row. A test makes `recordTaskAudit` reject and checks that the task was not created. day-08 replaces the call with `publishTaskEvent`, which takes the same arguments. That trades atomicity for best-effort delivery (ADR-006).
3. **bcrypt's limit is 72 bytes, not 72 characters.** `z.string().max(72)` counts UTF-16 code units, so a password of 37 × "é" (74 bytes) passed validation and would have been truncated without warning. Both schemas now check `Buffer.byteLength(password, 'utf8') <= 72`. Found in VALIDATE.
4. **The dummy hash is computed at startup.** It was first computed lazily, so the first unknown-email login also paid for that hash, making it slower than a real login. Found in VALIDATE.
5. **`jsonwebtoken`'s `expiresIn` type is `StringValue | number`, not `string`.** `env.ts` narrows `JWT_ACCESS_TTL` with a type-predicate `refine` (`/^\d+[smhd]$/`), so the code needs no cast.
6. **Recreate the anonymous `node_modules` volume.** `up -d --build` kept the old modules, and three suites failed with "Cannot find module 'jsonwebtoken'". The fix is `--renew-anon-volumes`, now in `knowledge/rules/coding-standards.md`.

## Verified end to end through Nginx (dev stack)

- Register returns 201 with `{ user: { id, email, createdAt }, accessToken, refreshToken }`, and `isAdmin` is stripped.
- A duplicate email returns 409 `EMAIL_TAKEN`.
- A wrong password and an unknown email return identical 401 `INVALID_CREDENTIALS` bodies.
- `/boards` and `/tasks` with no token return 401 `UNAUTHORIZED`.
- Creating, updating and deleting a task wrote CREATED, UPDATED and DELETED rows.
- The test password never appeared in the api logs.
